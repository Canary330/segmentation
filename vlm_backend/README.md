# vlm_backend 目录说明

这个目录存放的是项目里的提示式视觉语言分割后端核心代码。

简单说：

- `pure_visual` 负责“只看图像”
- `vlm_backend` 负责“图像 + 文字提示词”

这个目录对应的是申报书里后端大模型部分的核心实现。

## 当前目录里的文件

### `label_spaces.py`

这个文件负责定义不同数据源之间的标签映射关系。

它的作用是：

- 统一目标域 `13` 类标签
- 把公开数据中的标签映射到可训练的规范标签
- 解决“公开数据类别不完全一致”的问题

### `prompt_templates.py`

这个文件负责定义提示词模板。

它的作用是：

- 给每个结构提供多个自然语言提示词
- 训练时随机采样 prompt
- 推理时支持多 prompt 集成

这部分非常重要，因为项目不是简单分割，而是“医生输入结构名称即可分割”。

### `lora.py`

这个文件实现 `LoRA` 相关逻辑。

它的作用是：

- 对文本编码器进行轻量微调
- 避免每次都全量微调大模型
- 降低训练成本

### `data.py`

这个文件实现提示式分割的数据集读取逻辑。

它的作用是：

- 读取 `prepared/prompt_seg/*.jsonl`
- 加载图像、提示词和二值 mask
- 提供给 `train_vlm.py` 直接训练

### `model.py`

这个文件是整个 `vlm_backend` 里最核心的模型定义文件。

它的作用是：

- 构建 `Promptable MobileUNet-FPN`
- 接入文本编码器
- 把文本特征注入视觉分割网络
- 支持加载纯视觉最佳权重进行初始化
- 为训练脚本、评估脚本和后端接口提供统一模型构建方式

## 这个目录在整个项目中的位置

整个提示式路线可以理解为：

1. `scripts/` 先准备 prompt 数据
2. `vlm_backend/` 定义如何读取数据、如何组织 prompt、如何做 LoRA、如何构建模型
3. `train_vlm.py` 调用这里的代码完成训练
4. `evaluate_vlm_a4c13.py` 调用这里的代码完成 `13` 类评估
5. `flutter/fastapi_backend/main.py` 调用这里的代码完成在线推理

也就是说，这个目录是连接“训练、评估、部署”三件事的公共后端核心。

## 为什么这个目录要保留

如果删掉这个目录，下面这些能力都会受影响：

- 单提示词分割
- 多提示词集成
- `CLIP + LoRA` 微调
- 从纯视觉权重初始化到多模态模型
- 最终 `13` 类重组推理

所以它不是实验残留，而是当前项目后端的关键主体之一。
