# 前后端部署与服务器启动说明

这份文档专门回答三个问题：

1. 拿到这个仓库后，哪些东西要放到后端服务器
2. 哪些东西放到前端本地即可
3. 服务器上执行哪些命令，能够把当前最优结果直接跑起来

这份文档默认目标是：

- 不重新训练
- 直接使用当前最优结果启动系统
- 让 Flutter 前端连上云端推理后端

## 1. 当前系统的实际结构

现在这套系统可以分成两部分：

### 后端

负责：

- 加载训练好的最优权重
- 加载文本编码器
- 提供推理接口
- 返回单提示词分割和 `13` 类整体分割结果

对应目录：

- `flutter/fastapi_backend`
- `vlm_backend`
- `pure_visual`

### 前端

负责：

- 让你选择图像
- 输入提示词
- 调用后端接口
- 显示分割结果和叠加预览
- 导出 mask 和预览图

对应目录：

- `flutter/flutter_frontend`

## 2. 哪些东西放到后端服务器

如果你的目标是“直接把当前最优模型跑起来”，后端服务器至少需要下面这些内容。

## 2.1 必须上传到服务器的代码目录

建议把整个仓库上传到服务器，最省事。

如果你不想整仓上传，那么后端最少需要这些目录和文件：

- `flutter/fastapi_backend/`
- `vlm_backend/`
- `pure_visual/`
- `train_vlm.py`
- `evaluate_vlm_a4c13.py`
- `requirements-train.txt`

如果只是部署当前结果，不训练的话，其实最核心的是：

- `flutter/fastapi_backend/main.py`
- `vlm_backend/`
- `pure_visual/`

## 2.2 必须上传到服务器的模型文件

当前最优模型权重在本地这里：

- [best.pt](/Users/mico/Documents/za/git/segmentation/server_artifacts/20260321_proposal_best/files/best.pt)

这个文件必须上传到服务器。

建议在服务器上放到：

```text
/root/autodl-tmp/project/segmentation/server_runtime/best.pt
```

## 2.3 服务器上必须准备的文本编码器

当前后端不是只靠 `best.pt` 就能推理，还需要文本编码器目录。

推荐在服务器上用 `ModelScope` 下载到：

```text
/root/autodl-tmp/modelscope_cache/AI-ModelScope/clip-vit-large-patch14
```

这是因为当前最佳模型依赖这个文本编码器。

## 2.4 后端服务器上不一定必须上传的数据

如果你只是“直接跑推理演示”，这些不一定需要：

- 原始 XML
- `FOCUS-dataset`
- `prepared/a4c13`
- `prepared/prompt_seg`

这些数据只有在以下情况下才需要：

- 你要重新训练
- 你要重新评估
- 你要继续补实验

也就是说：

- 纯部署：不一定需要训练数据
- 重新做实验：必须带数据

## 3. 哪些东西放到前端本地

前端本地只需要这些：

- `flutter/flutter_frontend/`

建议连同下面这个说明一起保留：

- `flutter/README.md`

前端本地不需要：

- `best.pt`
- 文本编码器
- `vlm_backend`
- `pure_visual`

因为这些都在后端服务器上处理。

## 5. 服务器上直接跑当前结果的最短步骤

下面这套流程默认你已经把代码和权重传到了服务器。

## 5.1 进入项目目录

```bash
cd /root/autodl-tmp/project/segmentation
```

## 5.2 创建并进入 Python 环境

如果你已有环境，可以跳过。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
```

## 5.3 安装依赖

```bash
pip install -r requirements-train.txt
pip install modelscope
```

如果只跑后端推理，最核心依赖是：

- `torch`
- `torchvision`
- `transformers`
- `fastapi`
- `uvicorn`
- `python-multipart`
- `Pillow`

## 5.4 下载文本编码器到本地缓存

不要走外网官方源，直接用国内镜像生态的 `ModelScope`。

```bash
python3 - <<'PY'
from modelscope import snapshot_download
path = snapshot_download(
    'AI-ModelScope/clip-vit-large-patch14',
    cache_dir='/root/autodl-tmp/modelscope_cache'
)
print(path)
PY
```

下载完成后，确认得到类似目录：

```text
/root/autodl-tmp/modelscope_cache/AI-ModelScope/clip-vit-large-patch14
```

## 5.5 准备环境变量

当前最优模型建议使用以下环境变量：

```bash
export SEGMENTATION_MODEL_PATH=/root/autodl-tmp/project/segmentation/server_runtime/best.pt
export SEGMENTATION_TEXT_ENCODER=/root/autodl-tmp/modelscope_cache/AI-ModelScope/clip-vit-large-patch14
export SEGMENTATION_IMAGE_SIZE=384
export SEGMENTATION_BINARY_THRESHOLD=0.5
export SEGMENTATION_MULTICLASS_THRESHOLD=0.15
```

说明：

- `SEGMENTATION_MODEL_PATH` 指向当前最佳权重
- `SEGMENTATION_TEXT_ENCODER` 指向服务器上的本地文本编码器目录
- `384` 和 `0.15` 是当前最优结果所使用的关键部署配置

## 5.6 直接启动后端

```bash
uvicorn flutter.fastapi_backend.main:app --host 0.0.0.0 --port 8000
```

启动后可以先在服务器本机验证：

```bash
curl http://127.0.0.1:8000/health
```

正常应返回类似：

```json
{"status":"ok","model_loaded":false,"checkpoint_configured":true}
```

注意：

- 第一次只访问 `/health` 时，`model_loaded` 可能还是 `false`
- 真正调用一次推理接口后，模型才会实际加载

## 5.7 建议的常驻启动方式

为了避免终端关闭后服务退出，建议放进 `screen`：

```bash
screen -S seg_api
source .venv/bin/activate
cd /root/autodl-tmp/project/segmentation
export SEGMENTATION_MODEL_PATH=/root/autodl-tmp/project/segmentation/server_runtime/best.pt
export SEGMENTATION_TEXT_ENCODER=/root/autodl-tmp/modelscope_cache/AI-ModelScope/clip-vit-large-patch14
export SEGMENTATION_IMAGE_SIZE=384
export SEGMENTATION_BINARY_THRESHOLD=0.5
export SEGMENTATION_MULTICLASS_THRESHOLD=0.15
uvicorn flutter.fastapi_backend.main:app --host 0.0.0.0 --port 8000
```

然后按：

```bash
Ctrl+A
D
```

就能把服务挂到后台。

恢复查看：

```bash
screen -r seg_api
```

## 6. 本地前端如何连接服务器

如果服务器不能直接暴露端口，最稳的是做 SSH 隧道。

在本地电脑执行：

```bash
ssh -p <服务器端口> -L 18000:127.0.0.1:8000 root@<服务器地址>
```

成功后，本地地址：

```text
http://127.0.0.1:18000
```

就映射到了服务器上的后端。

## 6.1 启动 Flutter 前端

本地进入：

```bash
cd flutter/flutter_frontend
flutter pub get
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:18000
```

前端里填的后端地址也保持：

```text
http://127.0.0.1:18000
```

## 7. 直接部署当前结果时，到底哪些必须带

如果你想最小化传输量，只带这些就够了。

### 服务器必带

- `flutter/fastapi_backend/`
- `vlm_backend/`
- `pure_visual/`
- `requirements-train.txt`
- `server_artifacts/20260321_proposal_best/files/best.pt`

### 服务器必须自己准备

- `clip-vit-large-patch14` 本地文本编码器目录
- Python 环境

### 本地前端必带

- `flutter/flutter_frontend/`

### 非必须

这些不是“直接跑当前结果”必须的：

- `scripts/`
- `prepared/`
- 原始 XML
- 公开数据集
- `train.py`
- `train_vlm.py`
- `evaluate_vlm_a4c13.py`

但如果你后续要继续实验，还是建议整仓保留。

## 8. 如果以后要重新训练，需要比部署多带哪些

如果你不是只演示，而是要重新做完整实验，服务器上还需要：

- `scripts/`
- `train.py`
- `train_vlm.py`
- `evaluate_vlm_a4c13.py`
- `prepared/a4c13` 或原始 XML 与图像
- `prepared/prompt_seg` 或原始公开数据

此时建议不要只传部分文件，直接把整个仓库和数据一起上传。

## 9. 推荐做法

最稳的做法其实是：

1. 本地保留完整仓库
2. 服务器也保留完整仓库
3. 只把前端运行在本地
4. 后端和模型运行在服务器

这样最不容易丢东西，也最方便后续继续训练和改实验。
